## 实现

- 把已有每 64 词条一个 32 位偏移的稀疏锚点数组序列化为同名 `.cidx`，首次完整校验成功后才保存。
- 固定小端格式：64 字节头 + 锚点数组，不序列化 C++ 内存布局。头含 magic、格式版本、stride、词条数、idx/dict 长度、ifo CRC、修改时间及两个内容抽样 CRC；头及锚点数据分别有 CRC32。
- 快速加载验证文件长度、格式、版本、源文件信息、CRC、偏移递增性及最多 8 处锚点边界；不再遍历全部词条。
- idx 与 dict 各读取最多 8×512 字节均匀分布样本。cache 校验未通过、缺失或读取失败时，执行原有完整扫描并重新生成。
- 缓存先写 `.cidx.tmp`，关闭文件后回读逐字节比较，再替换正式缓存。中途掉电不会损坏词库源文件；临时文件不用于查询，下次重建会覆盖临时缓存。
- RAM 预留计入序列化字节数组和锚点数组同时存在时的峰值。将上传缓冲移出栈，避免串口触发的索引操作嵌套文件系统调用时栈溢出。
- 不可写或空间不足导致缓存保存失败时，当前索引仍可查词，后续会重新扫描。

## 文件变化与重建

常规替换词库会改变长度或修改时间；ifo 全文 CRC 和 idx/dict 固定样本可进一步识别变化。项目 USB 导入新源文件时主动使对应 cidx 失效。

快速检查不等同于每次全文件哈希：外部原地修改时若保留大小与修改时间，且变化不在样本范围，不能保证发现。这样的操作后用 Fn+Shift+R / reindex，或删除对应 cidx，进行完整校验。缓存 CRC 用于检错，不作为恶意篡改防护。

Fn+R / reload 使用磁盘缓存；Fn+Shift+R / reindex 强制完整重新校验启动词库、汉英、拼音并重建；restart 便于测试，status 显示加载方式、耗时和启动时间。
